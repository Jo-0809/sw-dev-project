## 2. 단위 테스트 케이스

팀원 수(3)만큼의 대상은 기존 테스트 코드(`tests/test_*.py`, `tests/conftest.py`)가 함수를 직접 불러 확인한 적이 없는 파일 3개다: `login_ctl.py`, `profile_ctl.py`, `presets.py`. 이 파일들은 기존 서버 테스트에서 앱을 켤 때(`presets.seed`)나 로그인 요청을 보낼 때(`login_ctl`) 간접적으로 실행되기는 하지만, 결과를 확인하는 테스트는 없었다.
`subscription.py`는 추가로 시험한 파일이다. 전용 테스트 파일은 없었지만 기존 `tests/test_source.py::test_source_list_hides_demo_kinds`가 시연 모드를 끈 상태의 `find`·`registered_sources`를 이미 확인하고 있어, UT-S-07은 그 테스트와 내용이 겹친다.

라이브러리는 pytest(`assert`, `parametrize`, `monkeypatch`, `tmp_path`). DB가 필요한 테스트는 테스트마다 빈 임시 DB를 쓴다(`tests/conftest.py`의 `unit_db`).

| 시점 | 결과 |
|---|---|

실패 7개는 같은 결함 하나다. `profile_ctl`이 학년을 비었는지만 보고 범위를 보지 않아 `0`·`5`학년이 그대로 저장되고, `abc`·`2.5`는 `int()`에서 `ValueError`가 나 화면에서 서버 오류(HTTP 500)가 됐다. 화면은 1~4학년 라디오 버튼만 보여 주지만 요청을 직접 보내면 들어간다. `GRADES = (1, 2, 3, 4)` 범위 검사를 넣어 학년 누락과 같은 메시지(UC2 예외 1)로 돌려주게 고쳤다.
